## 0. 先看这一条：上架前你必须知道的现实

**Chrome 应用商店对中国大陆用户不友好，这是硬约束：**

| 环节 | 需要梯子吗 |
|---|---|
| 注册开发者账号、访问后台 | 需要 |
| 提交审核、收款验证 | 需要 |
| **你的用户从商店安装** | **需要** |

也就是说，**上架商店 ≠ 国内朋友能方便地用上**。上架只解决"公开、可搜索、自动更新"，不解决"国内可访问"。

- 受众是**国内同事/朋友** → 开发者模式加载 ZIP（路径 A）实际体验更好，商店反而是负担。
- 受众是**公开的任意用户（含海外）** → 上架才有意义。

**两条路可以并存**：上架商店做公开渠道，同时保留 ZIP 给国内熟人。

### 2.3 详细描述 / Description

```
书签越存越多，最后变成一个没人敢打开的垃圾堆？这个扩展把它变回可用的知识库。

【核心流程：三阶段，安全可控】
1. 扫描并分类 —— 只读，不动你任何书签
2. 生成预览 —— 在「智能书签」文件夹里复制一份分类结果，你亲自检查对不对
3. 执行整理 —— 确认无误后再删除原书签，分类文件夹提升到书签栏

全程可撤销。撤销会把删掉的书签按原位置、原顺序还原。

【两种分类方式】
· 关键词规则 —— 离线运行、免费、无需任何配置，装完即用
· AI 智能分类 —— 接入任意兼容 OpenAI 协议的服务（DeepSeek、OpenAI、本地 Ollama 等），
  在大类下自动生成二级标签子文件夹，归类更准
· 认你现有的目录 —— AI 还能看到每个书签**现在放在哪个文件夹**（如「台州项目 / 可研报告」），
  于是能沿用你原有的归类习惯；像「网文创作」这种只有你自己知道的目录名，光看书签标题和网址
  是猜不到的。它只是参考：文件夹名与内容矛盾时以内容为准，「新建文件夹」「111」这类没意义的
  名字会被自动忽略。该功能可在设置页关闭（关闭后 AI 只看标题与网址）

【大类可以按你的书签增删】
出厂预置 11 个常用大类，装完即用；你也可以自由增删改名。书签多、觉得大类不够用（或有些大类
早已用不上）时，在设置里点「AI 建议大类」：它会读你的书签，在**你当前这张表**的基础上建议
补哪几个大类、减哪几个大类，并逐条给出理由与你现有书签数的依据。
所有建议都要你先勾选再点应用，应用后可一键撤销；AI 说要删掉一个装着几百个书签的大类这种建议，
会被本地规则直接驳回。

【细节设计】
· 根目录书签可选 —— 直接放在书签栏根目录的书签，默认视为常用入口、一律跳过保持原位；若你的书签大多平铺在根目录上（几乎没有文件夹结构），可在设置里勾选让它们也按同样规则参与整理。生成预览之后你再钉到根目录的，默认同样受保护
· 预览随书签重建 —— 每次生成预览都会清空重来，保证预览内容与当前书签一致，不会留下过期副本
· 执行前复检 —— 点「执行整理」时会按当前书签现状再核对一轮：期间被你钉到根目录的、预览里已找不到对应副本的，一律跳过不删。宁可少整理，也绝不误删
· 高频书签置顶 —— 用浏览记录找出你最常用的书签，平铺在所属分类的一级目录，不必点进二级文件夹才找到；同一文件夹内的直接书签也按使用频率从上到下排列。可在弹窗里逐个增减，也可在设置中整体关闭（读取浏览记录为可选权限，默认不申请，你需要时再授权；关闭后书签按收藏时间排列）
· 子文件夹收敛 —— 每个分类下最多 N 个子文件夹（可配）；书签太少的分类不强行细分，只含 1 个书签的子文件夹不建，且每一层都保留可直接点击的书签（可另开启三级子文件夹）。**书签数达到阈值（默认 10 个）的分类保证一定有二级文件夹**，不会因为分类标签给得不够细而整个分类平铺
· 顺序规范 —— 每一层都是「子文件夹置顶 + 直接书签按使用频率降序」：最常用的书签自动排在最上面，不用在一堆冷门收藏里翻找；没有访问记录的书签按收藏时间排列，顺序稳定不乱
· 重复书签检测 —— 仅检测或一键清理，由你决定
· 配置导出/导入 —— 换设备或重装后一键恢复，不用重填
· 右键菜单 —— 网页上右键「智能添加书签」，自动归类到对应文件夹

【隐私承诺】
你的书签数据只存在你自己的浏览器里，不上传到开发者服务器。
仅当你主动配置并启用 AI 分类时，书签标题与网址才会发送到你自己填写的那个 AI 接口；
默认还会带上每个书签**当前所在的文件夹路径**（用来沿用你原有的分类习惯，可单独关闭），

无论开关如何，都会先在本地滤掉「新建文件夹」「111」这类没有信息量的文件夹名与插件自己的预览文件夹。
设置页的「AI 建议大类」会发起同类请求（同样是发到你自己填的那个接口），除此之外没有任何数据外发。

开发者不收集、不存储、不转售任何用户数据。

【权限说明】
· 读取和整理书签 —— 这是扩展的核心功能

· 当前标签页 —— 右键添加书签时读取当前页标题与网址
· 浏览记录（可选）—— 仅用于「高频书签」：统计你访问得最多、最近的网址。安装时不申请，你开启该功能时才弹授权框；拒绝也不影响其他功能，可直接在弹窗里手动点星标记。只读访问次数与最后访问时间，不上传、不存储，可在设置中关闭
· 访问你填写的 AI 接口域名 —— 仅在启用 AI 分类时需要，且由你主动授权
```

## 3. 隐私权做法表单（Privacy practices）—— 拒审高发区

后台这个页签有 4 块，**逐项照抄**：

### 3.1 Single purpose / 单一用途（一句话）

```
本扩展的唯一用途是整理用户的浏览器书签：读取书签并按主题分类，生成整理预览，经用户确认后重建书签文件夹结构。
```

> 政策要求：一个扩展只能有一个**窄**用途。「分类 + 去重 + 右键添加」都归属于「书签管理」这一个主题领域，合规。不要在这里写「还能管理密码 / 清理缓存」之类无关功能。

### 3.2 权限理由（每个权限一个输入框）

| 权限 | 填写理由 |
|---|---|
| `bookmarks` | 扩展的核心功能是整理书签。需要读取书签树以进行分类、检测重复、生成预览、创建与删除书签及文件夹。所有操作均在本地完成，书签数据不会上传到开发者的任何服务器。 |
| `storage` | 在浏览器本地保存用户的偏好设置（分类表、目标文件夹、AI 接口配置、界面选项）与撤销历史。API Key 仅存于本地，不同步到云端。 |
| `contextMenus` | 提供「智能添加书签」右键菜单项，让用户把当前网页一键收藏到自动判定的分类文件夹中。 |
| `activeTab` | 用户点击右键菜单「智能添加书签」时，需要读取**当前标签页的标题和网址**，以创建对应书签条目并判断其分类。权限仅在用户主动触发该菜单项时临时生效，不常驻、不监控浏览行为。 |
| `optional_permissions: ["history"]`（**可选权限，安装时不申请**） | 用于「高频书签」功能：读取最近半年的浏览记录，按「访问次数 × 时间衰减」算分，找出用户最常用的网址，从而把这些书签平铺在所属分类文件夹的一级目录，减少点击层级。**该权限声明为可选权限：安装本扩展时不会要求，也不显示「读取浏览记录」警告；只有当用户在设置页开启（或在弹窗点击「开启」）「高频书签」时，才由用户操作触发 `chrome.permissions.request` 弹出授权框，用户可以拒绝。** 数据侧：只读取访问次数与最后访问时间，仅在内存中算分，不修改/删除/新增任何浏览历史，不上传，也不写入扩展存储。拒绝授权不影响分类、去重等其他功能——「高频书签」自动降级为「仅手动标记」（在弹窗列表点星，手动标记不需要任何权限）。用户可随时在设置页关闭该功能，或在 Chrome 扩展详情页单独撤销此权限。 |
| `optional_host_permissions: <all_urls>`（可选权限） | 用户在设置中自行填写 AI 分类接口地址（兼容 OpenAI 协议的任意服务，可为 DeepSeek、OpenAI 或本地 Ollama）。由于地址由用户决定、无法预先枚举，需声明为可选的全域权限。**该权限为可选：不启用 AI 分类时不会请求，且仅在用户于设置页保存 AI 配置时弹出授权提示，用户可拒绝。** |

> ⚠️ **`activeTab` 千万别删也别不写理由**。代码在 `service-worker.js` 的右键菜单回调里真实读取了 `tab.title` / `tab.url`。不写理由 → 被判「权限未说明」；写了错误理由 → 被判「权限与代码不符」。上面这条是准确的。
>
> ⚠️ **`history` 是可选权限，这条最容易填错**。可选权限**不需要**在「权限理由」里像必需权限那样逐条填（那个表单只列必需权限），但**必须**在描述、隐私政策和数据披露里讲清楚——因为它请求时仍会弹「读取您的浏览记录」警告。如果误把它写成必需权限的理由，会造成「填了一个 manifest 里没有的权限」这种自相矛盾。

### 3.3 数据使用披露（Data usage）

**勾选：**
- ☑️ **Web history（网站历史记录）**

**其余全部不勾：** 个人身份信息、健康、金融与支付、身份验证信息、个人通信、位置、用户活动、网站内容。

> ⚠️ **这一项必须勾，而且现在有两个独立来源，理由比之前更硬：**
>
> 1. 启用 AI 分类时（含设置页的「AI 建议大类」），**书签的标题和网址**会发送到用户自己填的 AI 接口。书签是 URL 集合，归类到「网站历史记录」最贴切。（请求里还会带上用户自己填写的分类名称与关键词——那是本地配置文本；以及**书签所在的文件夹路径**——默认开启、可在设置页单独关闭，这是用户自己的目录名、可能含私人信息，所以单独写明。一并写出来是为了与实现完全对齐。）
> 2. 启用「高频书签」时，扩展通过 `history` 权限读取用户**最近半年的浏览记录**（网址、访问次数、最后访问时间）用于本地算分。该权限为**可选权限**（`optional_permissions`），安装时不申请、用户开启该功能时才弹框——**但这不改变「要披露」这个结论**：只要存在「用户可能被读取浏览记录」的路径，就必须勾。
>
> 两者的数据都不离开用户设备（第 2 项完全不上传、不落盘），但**权限确实申请了、数据确实被读取了，就必须披露**——少勾比多勾危险，披露不足按违规处理。用户可拒绝授权、在设置页关闭「高频书签」、或切回「关键词规则」模式，此后扩展不再读取任何浏览记录。

**三个后续问题：**
| 问题 | 答 |
|---|---|
| 是否将用户数据出售给第三方？ | **否** |
| 是否将数据用于与单一用途无关的目的？ | **否** |
| 是否将数据用于判断信用度或放贷？ | **否** |

**数据流说明（若表单有补充说明栏，填这段）：**
```
书签数据仅存储于用户本地浏览器。当且仅当用户在设置中主动配置并启用「AI 智能分类」时，
书签的标题与网址会通过 HTTPS 发送至用户自行填写的第三方 AI 接口（由用户选择服务商），
用于返回分类结果。请求中还会包含用户自己的配置文本（分类名称与关键词），以及默认开启的
「书签所在文件夹路径」（用于沿用用户原有的分类习惯，可在设置页单独关闭；开关关闭后不含任何
文件夹信息。无信息量的文件夹名如「新建文件夹」在本地即被滤除）。开发者不运营任何接收这些
数据的服务器，无法接触、存储或获取用户书签数据。
用户可以随时在设置中切换回「关键词规则」模式，此后不再有任何数据外发。
此外，「高频书签」功能会读取最近半年的浏览记录（网址、访问次数、最后访问时间）用于本地算分，
该数据不发送至任何服务器、不写入扩展存储、也不与任何第三方共享。读取浏览记录所需的权限为可选权限，
安装本扩展时不会申请，仅当用户主动开启「高频书签」时才弹出授权框，用户可拒绝；拒绝后仍可在弹窗中
手动标记高频书签，或在 Chrome 扩展详情页随时单独撤销该权限。
```

## 7. 审核风险点与应对

| 风险 | 本插件现状 | 应对 |
|---|---|---|
| **请求了代码里没用到的权限**（占拒审 ~43%） | ✅ 已逐条核对：必需权限 `bookmarks` / `storage` / `contextMenus` / `activeTab` 均有真实调用点；`history` 已改为**可选权限**（`optional_permissions`），调用点见 `js/frequency.js`（`hasHistoryPermission` / `requestHistoryPermission`） | 别再新增必需权限。`activeTab` 的理由必须照 3.2 写准 |
| **敏感权限未说明** | ⚠️ `bookmarks` 属必需敏感权限；`history` 虽为可选，但申请时仍会弹「读取您的浏览记录」警告 | 已在描述、隐私政策与权限理由里逐条说明；**每个必需权限都要有非空、非模板化的理由**。`history` 即使不在必需权限表单里，也必须在描述/隐私政策/数据披露中讲清「可选、只读、不上传、不存储、可拒绝」 |
| 隐私政策缺失或 404 | ⚠️ 待托管 | 提交后自己点一遍链接验证 |
| **数据外传未披露** | ⚠️ 两处：AI 分类会把书签标题/URL 发给用户填的接口；「高频书签」会读取浏览记录（可选权限，用户授权后才读） | 3.3 已勾 Web history + 写明数据流。**这是本插件最容易被判「披露不足」的点** |
| 单一用途违规 | ✅ 全部功能归于「书签管理」 | 描述里不要出现无关功能 |
| 远程代码 / 混淆 | ✅ 代码全部在包内，无 `eval`，无外链脚本 | 交付前 `grep -rn "eval\|new Function" ` 再确认一次 |
| 截图与功能不符 | ⚠️ 待制作 | 用真实界面，别用设计稿 |
| 元数据夸大或关键词堆砌 | — | 描述里同一关键词别堆超过 5 次（尤其"书签""AI"） |
| **宽泛主机权限** | ⚠️ `optional_host_permissions: <all_urls>` | 强调这是**可选**权限、由用户主动触发授权、不启用 AI 时不会被请求。若仍被质疑，可改为枚举常用 AI 服务域名（代价：用户填其他服务需手工授权） |

**被拒之后怎么办：**
1. 拒审邮件会指明具体政策条款（如 `User Data Privacy` / `Permissions`）。
2. **改对应那一处**，递增版本号，重新上传。
3. 在 "What's new" 里写明改了什么，例如：
   `修正隐私披露：补充说明书签数据仅在用户启用 AI 分类时发送至其自行配置的接口。`
4. 不要在一次重提里夹带无关改动 —— 会触发对无关部分的重新审查。
5. 只有确信拒审判断有误时才走申诉；反复提交不合规内容会影响账号本身。

**提速技巧**：在提交时通常有个「给审核员的备注」栏，填上测试指引，审核员不用猜：

```
测试说明（无需登录即可完整测试）：
1. 点击扩展图标打开弹窗，点「扫描并分类」（默认关键词模式，无需任何配置）。
2. 点「生成预览」，书签栏下会出现「智能书签」文件夹，内含按分类归好的副本。
3. 点「执行整理」，原书签被整理进分类文件夹，分类文件夹提升到书签栏。
4. 点「撤销」可完整还原。
AI 功能需用户自行填写第三方接口地址与 Key，审核时可跳过（非默认路径，不影响其他功能验证）。
```

## 8. 上架后的维护

| 事项 | 要点 |
|---|---|
| 版本更新 | 每次都走审核，**无快速通道**。小改攒一批再发，别一周发五个补丁 |
| 版本号 | 必须严格递增（1.0.0 → 1.0.1 → 1.1.0） |
| **新增权限会重置用户信任** | Chrome 会禁用扩展并提示用户重新授权，很多用户就此不再启用。**必需权限集要在首次上架就定好**。⚠️ 1.1.0 曾把 `history` 放进必需权限，会让全部存量用户被禁用重授权；1.2.0 已修正为 `optional_permissions`，在用户启用「高频书签」时按需申请，不启用就不弹警告、也不会禁用扩展 | 以后所有「只有部分用户用得上」的权限（如 `downloads`、`notifications`、更多 host 权限）一律走 `optional_permissions`，在对应功能开关里按需申请 |
| 灰度发布 | 后台支持按百分比灰度，改动大的版本用它 |
| 看数据 | 后台分析里「曝光高、安装率低」通常说明列表页有问题（截图或简短描述） |
| 回评 | 公开回复评价，能显著改善列表页观感 |
| 保持同步 | 截图/描述与当前版本不符，上线后也可能被判元数据问题 |
